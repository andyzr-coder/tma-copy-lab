# TMA Copy Lab

一个公开、无需登录的中文交互教学网站，先用独立的 **COPY 入门动画** 学会基础搬运，再用小矩阵解释 **concat、slice、im2col 如何拆成基础 copy 搬运**。

在线访问：**https://andyzr-coder.github.io/tma-copy-lab/**

这个仓库独立于 ADA300 硬件项目。仓库中只有网站、教学地址模型和测试，不包含原始 RTL、Word 规格、凭据或实际设备数据。

## 怎么学

1. 从 COPY 开始：原样复制三行，再选“每行只搬一段，两边行距不同”。调整源/目的列起点与行距，灰色“—”表示保持原值，不是补零。
2. 切换 concat，播放 A、B 分别写入输出的过程。
3. 切换 slice，改变起点、区域大小和正步长，观察源地址与目的地址的关系。
4. 切换 im2col，比较按窗口、按核位置与核行分组。
5. 选择对齐示例，对照描述符、硬件检查和带宽成本。

支持播放 / 暂停、前后单步、进度拖动、点击格子追溯来源、点击指令跳转、输出矩阵分页、通道切换、参数链接分享，以及描述符 JSON 下载。

## 模型和拆分

- `copy`：一条二维描述符；可调整每行搬运量、两侧行距及列起点。未选中的目的位置保持原值。主页默认进入此入门页，旧算子参数链接继续有效。
- `concat`：两输入沿一个轴拼接，未拼接轴相等；每个输入一个矩形 copy。
- `slice`：连续矩形使用一个 copy；正的取行步长通过源行距表达；隔列取样按输出列段拆分。
- `im2col`：采用 NHWC 输入与 `[N×P×Q][R×S×C]` 输出，一个窗口占一行；包括三个可对比的拆分策略。
- 核位置策略：stride 为 1 时，每个 batch、核位置的有效输出区域是矩形，使用三维 copy；padding 先由外部清零，再仅搬有效区域。其他 stride 使用每个 `n,p,r,s` 一条二维 copy，沿有效 q 范围搬运。
- 窗口策略：按窗口、核行搬连续段，横向 dilation 大于 1 时进一步拆开。
- 每个可视格表示一段连续元素，通道控件只改变显示哪一个元素；实际模型搬运整段。
- 普通 copy 不产生 padding 的零。清零作为外部前置步骤，不混入 copy 指令计数和有效搬运量。

## 参考与边界

固定参考版本：`64cda54608278fc973be7132cc7f338b699adaeb`。

本网页实现独立的精确地址教学模型，以及普通 linear→linear CP 的部分静态检查：基地址 128B 对齐、行距 256B 对齐、dim0 坐标 128B 对齐、CONV/MATMUL 宽度取整、取整后 box 的几何边界。导出示例统一使用 CONV 模式，字段为 CP 风格描述符，base 为相应缓冲区内的字节偏移。

**动画正确和检查通过，都不代表已经通过 RTL 仿真或可以直接下发设备。** 真正执行仍需有效物理地址、分配边界、通道字段转换和系统验证。LD/ST 与 CP 不使用完全相同的描述符。batch 由外层循环推进，不假设原生四维 walker。

不模拟卷积乘加、burst 逐周期时序、总线反压、bank conflict、实测性能、折叠布局、transpose、gather/scatter、SWA、4bit 打包、量化零点、负步长 slice 或重叠源目的缓冲区。

参数为教学而限幅：输入空间尺寸 2–7，核尺寸 / stride / dilation 1–3，padding 0–2，batch 1–2，每格元素数最多 128；支持 8/16/32bit 元素。网页不上传用户输入，资源不依赖第三方 CDN。

## 本地运行

无构建步骤，使用任意静态 HTTP 服务，例如：

```sh
python -m http.server 8766
```

打开 `http://localhost:8766`。ES modules 需要通过 HTTP 打开，建议不要直接双击 HTML。

## 验证

```sh
node --test tests/engine.test.mjs tests/performance.test.mjs
```

测试使用独立的输出映射，对照每一条描述符的地址遍历，覆盖不同元素宽度、向量长度、slice 步长，以及 240 组卷积参数下的三种 im2col 策略；另外检查空输出、全 padding、对齐取整和越界情况。

浏览器检查需要本机可用的 Playwright 和 Chromium：

```sh
node tests/browser.cjs
node tests/performance-browser.cjs
```

可以通过 `TEST_URL` 更换站点地址、`BROWSER_EXECUTABLE` 指定浏览器。浏览器检查覆盖实际播放和暂停、参数修改、指令跳转、通道选择、JSON 下载、URL 参数恢复，以及 1440 / 390 / 320px 布局。QA 结果仅生成在被忽略的 `.qa/` 目录。

## V2：带宽优化方案与实现

目标是先保证拆分正确，再在当前候选中选择较低的估算搬运成本，保留三种策略的逐段动画。站点仍独立于 ADA300 项目。

1. **保留真实形状和正确性检查。** 不自动扩大 C 或多写相邻有效元素。不符合对齐/取整/几何条件的候选只展示地址动画，没有总线耗时或加速百分比，也不参与推荐。
2. **新增核行分组。** 连续核列一起搬；固定 n,p,r 和相同有效核列区间，令 g=ceil(连续核列数/stride_w)，按 q mod g 分组，使 src_pitch=g×stride_w×C 至少容纳 box0。每组成为二维 COPY。padding 边缘按有效区间分开；dilation_w>1 时拆为单格。该方案不减少逻辑重复读取，不保证指令最少。
3. **按两个端点分别统计。** 遵循参考 rd_ctrl/wr_ctrl：box0=glb0 合并行，进一步 box1=glb1 合并面；不跨指令合并或缓存复用。每拍128B，L1每请求1拍；MIF最多32拍且不得跨4KB。64B行仍占128B拍容量。请求数依赖可调的物理基地址页内偏移。
4. **按假设比较成本。** 带宽默认32GB/s、每请求不可隐藏开销2ns、每指令50ns只是教学输入。共用带宽按读写容量求和，独立带宽取两侧数据项较大值。整输出清零是先完成的额外外部写操作，单独加入流量和启动开销。请求开销不是响应延迟；不把 outstanding 请求的所有往返延迟简单相加。按三候选中合法者排序，可一键应用建议并继续播放。
5. **按情形给解释。** 连续 concat/slice 已利用控制器自动合并，扁平化未必提高性能；小 C、窄切片、隔列取样首先检查可表达性；大 C、连续核行比较 burst 与指令启动；padding 单计清零；stride/dilation 可能减少连续性或复用机会。
6. **片上分块仅作架构对照。** 独立假设输入和中间矩阵原在外存，并有一次后续完整读取；基线字节=有效读取+有效写入+整输出清零+后续读取。假设优化方案把输入外接矩形逐块加载，片上展开后直接消费，不回写中间矩阵。块间不复用重叠边缘，内部stride/dilation空洞仍加载。峰值空间=输入矩形+一份展开输出；空间不足则明确不适用。未实现片上重排内核、卷积、双缓冲，不将这个对照作为可执行COPY候选。

`performance.mjs` 可独立复现读写请求与成本。JSON 导出附带全部假设、候选统计、推荐策略和片上分块对照。URL 保留策略和性能参数。

端点菜单只选择流量模型，并不生成 CP/LD/ST opcode。MIF↔MIF 是端点流量对照；原生 CP 通道支持范围仍遵从页面中的通道说明。实际部署需映射原生指令、提供物理缓冲区并做 RTL 仿真。性能排名仅是此成本公式和三个候选的结果，不是最优性证明或硬件性能保证。
