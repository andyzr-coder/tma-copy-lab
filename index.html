V2 / 在搬对之后，比较搬运成本

指令少，不等于带宽利用率高。

请求模型 + 可调假设

同一份输出，比较有效字节、128B 数据拍和端点请求。先排除不符合硬件约束的方案，再按假设估算成本。动画速度不代表硬件时间。

COPY 指令像一张搬运任务单；控制器把任务拆成请求，再用数据拍传送。这里一拍能装 128B。MIF 一个请求能连续传最多 32 拍（一个 burst）；L1 一个请求只传一拍。所以“一条 COPY”“一次请求”“动画的一步”是三个不同的量。

展开开销、物理地址和估算公式

本版普通路径：每拍 128B；L1 每请求 1 拍；MIF 每请求最多 32 拍，并在 4KB 边界拆开。读写分别按各自地址合并连续行/面，不跨指令复用。A、B 为独立缓冲区，使用同一输入页内偏移假设。

成本 = 数据传输项 + 请求数 × 不可隐藏请求开销 + 指令数 × 启动开销。共用带宽时，数据项为读写容量之和 ÷ 带宽；独立带宽时取读、写数据项的较大值。若有补零，先加整块输出清零的写入项，再计算 COPY；清零按额外一次外部操作估算。

默认 32GB/s、2ns、50ns 只是可调教学假设，不是芯片规格。请求开销不是内存响应延迟；实际硬件有 outstanding 和流水线。这里不模拟排队、反压、频率、bank conflict 或调度重叠，不能把结果当实测耗时。

端点选项用于流量比较，并不切换 CP opcode 或生成完整 LD/ST 指令。所有候选仍使用统一 CP 风格地址视图；实际执行需要端点字段映射与验证。

遇到这些情况，怎么选？

这次采用的优化方案，以及为什么不总选同一种

① 正确性优先：保持真实 C 和数据布局；先检查基址、行距、起点、box 取整与边界。不能把 C=1 偷换成 C=128 来制造高利用率。不合法的拆法仍可播放教学动画，但不计算硬件时间、不参与推荐。

② 三个可播放的 im2col 候选：按窗口保留较宽的连续核行；按核位置通常指令较少，读端可能自动合并；新增核行分组在相邻核位置之间保持连续，通过 q 的余数分组让源行距容纳整段。stride、dilation 和 padding 会改变候选数量和可执行条件。

③ 按端点成本选：L1 的每个 128B 拍都需一个请求，长段并不自动减少 L1 请求；MIF 可以把连续拍放入同一个 burst。读端变连续，不代表写端也连续。按当前假设，在通过检查的三个候选中选最低成本；不是全局最优搜索。

④ concat / slice 先看现有合并：整行连续时，RTL 已合并行/面；再扁平化不一定更快。横向 concat、窄 slice 或隔列取数仍可能产生碎片。减少无用搬运、让生产者直接写最终位置或让下游接受视图，需要上层接口配合。

⑤ 流量仍大，再考虑片上复用：下方给出容量受限的分块架构对照。普通 COPY 没有自动跨窗口缓存；实现这一步还需片上重排、清零与计算消费的衔接。

进一步优化 / 架构假设，不是已生成指令

把一块输入留在片上，让多个窗口共用。

独立假设：输入与完整 im2col 中间矩阵原本都在外存，计算端之后完整读取中间矩阵一次。比较只涉及数据重排的逻辑外存流量，不含权重和卷积最终输出，也不含总线取整。

每块加载有效输入的外接矩形，包含 dilation / stride 跳过的内部数据；不同块之间不复用重叠边缘。容量包括一份输入矩形和一份展开输出，不含双缓冲、权重与计算工作区。这里只统计架构所需的字节和空间，没有生成片上重排或卷积执行代码；原动画继续展示所选 COPY 方案。

矩阵，是数据的排列方式

行和列让我们容易看懂数据。内存里却是一串地址。线性排布通常先放完一行，再放下一行；NHWC 图像会把同一个像素的 C 个通道连续存放。

第 0 行 → 第 1 行 → 第 2 行
02

box：这次要搬多大

box0 是每行搬多少个元素，box1 是搬多少行，box2 是搬多少面。维度按 (dim0, dim1, dim2) 书写，dim0 变化最快。

box = (每行元素数, 行数, 面数)
03

global：下一行从哪里开始

glb0 × E 是行距，E 是每元素字节数。每行只取 3 个元素，也可能需要跨过整行 8 个元素，才能到下一行的相同位置。

搬 3 个 ≠ 下一行只前进 3 个
04

源和目的，可以有不同的行距

读端按源的排布前进，写端按目的的排布前进。这正是 slice、concat、im2col 能复用 copy 的原因。起点由 base + start 对应的地址偏移确定。

读 256B → 写 256B → 各自换行
展开：地址计算公式与单位

对一个端点，当前子块内坐标是 (x,y,z)，元素字节数为 E：

addr = base + E × [ (start0 + x)
                   + (start1 + y) × glb0
                   + (start2 + z) × glb0 × glb1 ]

0 ≤ x < box0，0 ≤ y < box1，0 ≤ z < box2

源、目的各算一次。base 是字节地址；glb、box、start 是元素数或对应维度坐标。不要把 128 个 FP16 元素误写成 128B，它们实际是 256B。普通 walker 的面距由 glb0×glb1 得到，不能随意独立指定。

把名字和用途对上

三个算子，三个不同的目的。

CONCAT

拼接

把几个输入沿某个方向接起来。例如把两张表左右并排，或把两批样本上下连接。拼接轴可以长短不同，其他轴必须相同。它改变数据的排列，不改变数值。

拆法：每个输入一条 copy，写入输出中为它预留的位置。横向拼接改变目的列起点，纵向拼接改变目的行起点。动画中用不同标记区分 A、B；B 的示例数值从 10001 开始。

A + B → [ A | B ]输入各搬一次
SLICE

切片

从原数据中选出一个区域，例如裁出图像的一小块，或只保留某些行列。这里的“步长 2”表示每隔一个位置取一个，不是搬两份。

拆法：连续矩形只需修改源起点和 box，保留源行距；多个输出块分别发 copy。隔列取样时，列之间不连续，本实验按输出列拆成窄 copy。隔行可以通过增大源行距表达。

大矩阵 → 一个子块没被选中的数据不搬
IM2COL

窗口展开

卷积要反复查看小窗口。im2col 把每个窗口里的数据拉直成一行，让后续计算可以用矩阵乘法处理。虽然名字带 col，本实验遵循给定规格：一个窗口对应输出的一行。

它只复制和重排输入，没有与卷积权重相乘，也没有求和。窗口重叠时，一个源像素会出现在多个输出位置，所以输出可能比输入大很多。

stride 决定下一个窗口移动多远；dilation 决定核内相邻采样点隔多远（无空洞为 1）；padding 在边界补零；C 是每个像素的通道数。固定核位置后，可以把多个窗口的同一段通道成批搬运。

[N,H,W,C]
↓
[N×P×Q, R×S×C]P、Q 是输出窗口的高和宽
展开：im2col 输出尺寸和元素对应关系
P = floor((H + 2×pad_h − dilation_h×(R−1) − 1) / stride_h) + 1
Q = floor((W + 2×pad_w − dilation_w×(S−1) − 1) / stride_w) + 1
K = R × S × C

m = (n×P + p)×Q + q
k = (r×S + s)×C + c
h = p×stride_h − pad_h + r×dilation_h
w = q×stride_w − pad_w + s×dilation_w

Y[m,k] = X[n,h,w,c]    （h,w 在输入范围内）
Y[m,k] = 0              （h,w 越界，由预先清零保留）

当 P 或 Q 不大于 0，本实验显示“没有输出窗口”，不会生成负尺寸搬运。规格示意图如果把 dilation=0 用来表示“零个空洞”，对应本网站的 dilation=1。

  • 按固定 RTL 版本检查线性 CP 的对齐、实际宽度取整和几何边界。
  • 导出当前描述符，分享带参数的页面地址；所有计算在浏览器本地完成。

不能从动画推断

  • 带宽成本是有明确假设的估算。请求模型考虑连续段合并、128B 拍、MIF burst 和 4KB 边界；不模拟流水线时序、反压、排队或 bank conflict，也不代表 RTL 实测性能。
  • 不实现卷积乘加，也不实现硬件 padding 指令。补零作为独立前置步骤。
  • 不生成完整 ISA 机器码，不接真实设备，不保证所有端点都接受 CP 字段。
  • 不覆盖折叠布局、转置、gather/scatter、SWA、量化零点或 4bit 半字节打包。
  • 假设源目的缓冲区不重叠、已分配且满足真实地址边界；不模拟并发命令；成本模型的基地址页内偏移是可调假设。
  • 这里只演示正步长 slice；不覆盖负步长反转、不规则索引或全部张量布局。

图中的 copy，最后应该发给谁？

copy 在这里是“基础搬运”的统称。LD 把全局存储的数据搬到 L1 tile；ST 把 L1 tile 搬到全局存储；原生 CP 支持本地 L1→本地 L1、远端 L1→本地 L1、DLB→DLB。截图中的红圈属于 ST，不能把它的指令一律替换成 CP opcode。

本网站为了统一展示，使用 CP 风格的 src/dst 描述符。实际 LD/ST 需映射到 global tensor 与 L1 tile 两套字段，并检查各自通道的限制。当前参考实现没有独立的 concat/slice/im2col 展开器；可以由上层生成基础搬运序列，或者另加硬件描述符生成状态机。
